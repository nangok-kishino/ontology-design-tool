# 新しいデータモデル（合意事項）

2026-11-01 の打ち合わせで決まったこと。決まっていないことは書かない。

---

## 1. アプリの位置づけ

**Neo4j に登録する前に、きれいに・正しくグラフを作るためのツール。**

- スキーマの設計（ラベル／リレーションシップタイプ／プロパティ）、ノード・リレーションシップの作成、
  文書からの抽出、名寄せ、承認までがこのアプリの担当
- できあがったグラフの探索・可視化は Neo4j（Aura / Explore / Bloom）に任せる

したがって**グラフビューは廃止**する。スキーマビューはデータの可視化ではなく設計そのものなので残す。

## 3. 構造の変更

### 3-1. ラベルは親子関係を持たない

`parentId` を廃止する。名前・英名・説明・同義語・グループ・並び順・承認履歴はそのまま流用できる。

### 3-2. ノードは複数のラベルを持つ

`classId`（1つ）→ `labelIds`（複数）。
これまで子クラスに属していたインスタンスには、**祖先のラベルもすべて付与**する。

```
これまで: ポンプA { class: 遠心ポンプ },  遠心ポンプ { parent: 設備 }
これから: ポンプA { labels: [遠心ポンプ, 設備] }
```

これにより、これまで「子クラスは親クラスのリレーションを継承する」として推論していたものが、
ただのラベル付与になる。ラベルペアの判定も、祖先を辿る探索から
「ノードのラベルにそれが含まれるか」という単純な判定になり、継承の効果はそのまま残る。

**注意点**：階層がないので、新しくノードを作るときに上位ラベルを付け忘れると、
そのノードは静かにリレーションシップの対象外になる。何らかの補助（実績ベースのラベルサジェストなど）が要る。
ただし「ラベルAを付けたらBも自動付与」という設定は作らない（親子関係の復活になるため）。

### 3-3. プロパティ

ノードが持てるプロパティは、**付与された全ラベルのプロパティの和集合** ＋ プロジェクト共通。
同名のプロパティが複数のラベルにある場合は、同一のものとして1つの入力欄にまとめる。

### 3-4. ラベルペア（始点終点の事前指定）は踏襲する

当初は廃止する案だったが、リレーションシップの品質担保に効いているため残す。
`classPairs` → `labelPairs` と改称して、意味はそのまま。

これは3つの仕事をしている。

1. スキーマビューの辺そのもの
2. リレーションシップの型チェック
3. 抽出のガードレール（「許可ペアに一致する組み合わせだけを抽出せよ」）

## 4. カテゴリノード

これまでの「端がクラスのトリプレット」（支柱 ─[規格に基づく]→ JIS S1039 など）は、
ラベルがノードではない以上そのままでは表現できない。

**カテゴリ自体をノードとして作る。**

```
支柱ノード { name: "支柱", labels: ["支柱", "カテゴリ"] }
支柱ノード ─[規格に基づく]→ JIS S1039
```

特別扱いのコードは要らない。リレーションシップタイプ〈規格に基づく〉のラベルペアが `支柱 → 規格` なら、
支柱ノードは `支柱` ラベルを持つのでそのまま検証を通る。

### 予約ラベル「カテゴリ」

`支柱` ラベルだけだと個体（ERL-01-01 など）と区別が付かないので、予約ラベル **`カテゴリ`** を併用する。

```cypher
MATCH (n:支柱) WHERE NOT n:カテゴリ   // 個体だけ
MATCH (n:支柱:カテゴリ)                // カテゴリノードだけ
MATCH (n:支柱)                         // 両方
```

「すべての支柱が規格に基づく」はカテゴリノードに生えた1本の辺になり、個々の支柱ノードからは直接辿れない。
個体ごとに辺を複製するより1本で持つほうが正しいので、これでよいとする。

## 5. 同義語・別名・名寄せ辞書

似た言葉が3つあって紛らわしかったので整理する。

| | 対象 | 誰が決める | 例 |
|---|---|---|---|
| **同義語** | ラベル（種類） | 人が設計時に手で登録 | 「商品」の同義語に「製品」 |
| **別名** | ノード（個体） | 名寄せで統合したとき自動で吸収 | 「ポンプA」が「P-A」を吸収 |
| **名寄せ辞書** | ノード（個体） | 名寄せを人が承認した記録 | 「P-A」→ ポンプA、承認者・日時・根拠 |

**同義語は「種類」の言い換え、別名は「個体」の言い換え。**

なお、これまでの「同義語辞書」画面とクラス編集パネルの同義語欄は、同じデータを編集していた
（横断編集ビューと1件編集の違いだけ）。別の辞書が2つあったわけではない。

画面名は「辞書」を片方にしか使わないようにする。

- **ラベル同義語**（スキーマ設計）
- **ノード名寄せ**（グラフデータ作成）

## 7. 進め方

別アプリにはせず、**同じリポジトリで作り替える**。
認証・Cosmos接続・プロジェクト管理・グループ・承認機構・名寄せ・成立条件・LLM配管・
インポート/エクスポートの骨格・UIキットは、今回の変更と無関係にそのまま使えるため。

データは、手元の YAML を経由せず、**Cosmos の今のデータを直接読んで新しいコンテナに書く**。
旧コンテナには書き込まないので、何度でもやり直せる。多少の抜け漏れは許容する。
